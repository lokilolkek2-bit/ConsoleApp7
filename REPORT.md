# Отчёт: реализация асинхронного TCP-сервера

## Цель работы

Переработать TCP-сервер так, чтобы он мог обслуживать несколько клиентов одновременно, не ожидая завершения работы с предыдущим клиентом, а также корректно переживал отключение клиента.

## Исходная реализация

В исходном `Program.cs` методы чтения и записи уже использовали `async`/`await`, однако цикл приёма подключений выполнял `await HandleClientAsync(client)` непосредственно. Из-за этого сервер не принимал следующее подключение, пока текущий клиент оставался подключённым. Таким образом, сетевые операции были асинхронными, но обслуживание клиентов происходило последовательно.

## Выполненные изменения

1. После принятия подключения обработка клиента запускается отдельной задачей `HandleClientAsync`, а цикл приёма сразу возвращается к `AcceptTcpClientAsync`.
2. Активные подключения хранятся в `ConcurrentDictionary`, безопасном для доступа из нескольких задач.
3. Чтение и отправка данных выполняются асинхронно через `NetworkStream.ReadAsync` и `WriteAsync`.
4. Возврат `0` из `ReadAsync` трактуется как штатное закрытие соединения клиентом.
5. Для каждого клиента предусмотрены обработчики отмены операции, `IOException`, `SocketException` и закрытия сокета. В блоке `finally` клиент удаляется из списка и освобождает ресурсы.
6. Добавлена остановка по `Ctrl+C`: прекращается приём новых подключений, закрываются активные сокеты и ожидается завершение клиентских задач.
7. Сохранено исходное поведение прикладного протокола: обычный текст возвращается в верхнем регистре, команда `PING адрес` выполняет HTTP-запрос и возвращает время ответа и HTTP-статус.

## Используемые средства .NET

- `TcpListener` — прослушивание TCP-порта 5000.
- `TcpClient` и `NetworkStream` — работа с подключением и сетевым потоком.
- `AcceptTcpClientAsync`, `ReadAsync`, `WriteAsync` — асинхронные сетевые операции.
- `Task` — независимое выполнение обработчика каждого клиента.
- `ConcurrentDictionary` — хранение активных подключений и задач.
- `CancellationTokenSource` — управляемая остановка сервера.
- `try/catch/finally` — обработка ошибок и гарантированное освобождение ресурсов.

## Порядок проверки

1. Запустить приложение командой `dotnet run` из каталога `ConsoleApp7`.
2. Открыть два TCP-клиента и подключить их к `127.0.0.1`, порт `5000`.
3. Отправить текстовые сообщения от обоих клиентов. Сервер должен вернуть каждое сообщение в верхнем регистре.
4. Закрыть соединение первого клиента.
5. Продолжить отправку сообщений от второго клиента. Сервер должен продолжать работу.
6. Остановить сервер сочетанием `Ctrl+C`.

## Ожидаемый результат

Сервер принимает несколько подключений, независимо обрабатывает данные каждого клиента и продолжает обслуживать оставшиеся соединения после отключения одного из клиентов. При остановке сервера активные подключения закрываются корректно.

## Вывод

В результате исходная последовательная обработка TCP-клиентов заменена конкурентной асинхронной обработкой. Сервер не ожидает завершения сессии одного клиента перед приёмом следующего. Добавлены обработка отключений и ошибок соединения, а также управляемое завершение приложения.

> Примечание: скриншоты фактического запуска необходимо сделать после запуска проекта в среде .NET 8. В текущей среде SDK .NET отсутствует, поэтому локальная сборка и реальный сетевой тест здесь не выполнялись.
